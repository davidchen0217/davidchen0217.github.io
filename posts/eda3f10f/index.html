說明：

  • 用 crontab -u 建立的檔案會放在 /var/spool/cron/[username]，而且擁有者會自動設定成該使用者，不需要再手動 chown
  • 排程會用該使用者的權限執行。像 ntpdate、hwclock 這類修改系統時間的指令需要 root 權限，一般使用者的 crontab 執行會失敗，這種排程應該放在 root 的 crontab
  • crontab 的環境變數很少（PATH 很短），指令最好都寫完整路徑

登入後提示字元變成 -bash-4.2$

情境

登入 Linux 後，提示字元是 -bash-4.2$，而不是平常看到的 [帳號@主機名稱 目錄]$。

原因

提示字元的格式（PS1）是在登入時由 ~/.bash_profile → ~/.bashrc → /etc/bashrc 這條鏈設定的。如果這個使用者的 ~/.bash_profile 或 ~/.bashrc **被改壞、被刪除，或沒有載入 /etc/bashrc**，就會使用 bash 預設的提示字元 -bash-4.2$（4.2 是 bash 的版本）。
