找回 Token

忘記 Token 時，可以向 BotFather 查詢：

  1. 找到 @BotFather
  2. 輸入 /mybots
  3. 列出你建立過的 Bot，點選要查詢的 Bot
  4. 點 API Token，就會顯示 Token

Token 等於 Bot 的密碼，不要寫進公開的程式碼或文件。外洩的話，可以在 BotFather 用 /revoke 作廢並產生新的 Token。

升級成 Supergroup

升級步驟

  1. 建立群組
  2. 加入一位好友
  3. 把好友設為管理員，並開啟所有權限
  4. 群組就會升級成 Supergroup，可以用 getUpdates 確認新的 chat_id

怎麼分辨是不是 Supergroup

chat_id 以 -100 開頭的就是 Supergroup，一般群組則是單純的負數。

注意：升級後 chat_id 會改變

一般群組升級成 Supergroup 後，chat_id 會變成新的值。如果程式還用舊的 chat_id 發送，API 會回傳錯誤，並在 parameters.migrate_to_chat_id 裡告訴你新的 chat_id。升級後記得更新設定。

Long Polling 與 Webhook

Bot 接收使用者訊息有兩種方式：

Long Polling（getUpdates）Webhook
運作方式程式定期呼叫 getUpdates 拉取新訊息向 Telegram 註冊一個 callback URL，有新訊息時 Telegram 主動 POST 過來
優點不需要對外的伺服器，設定簡單即時、不浪費資源
缺點浪費資源、不夠即時需要有固定 URL 和 HTTPS 憑證的伺服器
適合開發和測試階段已部署、有固定 URL 的正式環境

發送限制與錯誤處理

400 Bad Request: message is too long

依照 Telegram API 文件，一則訊息最多 4096 個字元。超過的話要自己切成多則發送。

429 Too Many Requests

Telegram 官方 FAQ 的建議：

  1. 在同一個聊天裡，避免每秒發送超過 1 則訊息
  2. 整體來說，API 每秒不允許超過約 30 則訊息
  3. 對群組發送，每分鐘不要超過 20 則

我們實測的情況是：在群組裡連續發 10 則訊息後，必須等約 40 秒才能再發，等待期間發送的訊息都會失敗而遺失。

收到 429 時，要依照回應中的 retry_after（秒）等待後再重送。發送大量通知時，建議在程式裡實作佇列和限速，並合併相近的通知，不要一個事件發一則。
