JDK 20 起 new URL() 被標為 deprecated：原因與改用 URI.toURL() 的寫法

發表於 2024-09-15 更新於 2026-11-27 分類於 URL 閱讀次數： Disqus： 文章字數： 1.6k 所需閱讀時間 ≈ 3 分鐘

升級到 JDK 20 以後，new URL("...") 會出現 deprecation 警告。原因是 java.net.URL 的建構子不會依照 RFC 2396 編碼或解碼網址，容易造成錯誤甚至安全問題。這篇說明為什麼被棄用，以及改用 URI.create(...).toURL()、Path.toUri().toURL() 的寫法。

OpenJDK Quality Group 在 2023 年 2 月的〈Quality Outreach Heads-up - JDK 20: Deprecate URL Public Constructors〉中公告了這項變更，以下是我的整理。

為什麼要棄用

java.net.URL 從 Java 1.0 就存在，它的建構子不會依照 RFC 2396 對網址的各個部分編碼或解碼：

  • 呼叫端必須自己把需要跳脫的字元先編碼，例如空白、中文
  • 從 URL 取回的欄位，也要自己解碼

很多程式沒注意到這點，結果造成各種使用上的問題，甚至安全漏洞。Java 1.4 加入的 java.net.URI 就是為了改善這些缺點，它會檢查格式並正確處理編碼，也提供轉成 URL 的方法。

所以 JDK 20 把 java.net.URL 的所有 public 建構子都標為 deprecated，用明確的警告引導開發者改用 URI。

現有的程式要馬上改嗎？

被標為 deprecated 不代表已經移除，現有程式在 JDK 20 以後仍然可以編譯和執行，只是會出現警告。不過新寫的程式應該直接用 URI；既有程式可以趁維護時逐步替換，順便檢查原本有沒有因為沒編碼而潛藏的錯誤。
