重構手法 Replace Temp with Query 與 Split Temporary Variable：把暫時變數換成查詢方法

發表於 2020-06-18 更新於 2026-11-26 分類於 Refactor 閱讀次數： Disqus： 文章字數： 2.7k 所需閱讀時間 ≈ 5 分鐘

方法裡的暫時變數，常常是把長方法拆開的最大阻礙：想 Extract Method，卻發現一堆變數得當參數傳來傳去。Replace Temp with Query（以查詢取代暫時變數）就是把「計算暫時變數的表達式」搬進一個方法，用呼叫方法取代變數。如果同一個變數被重複拿來存不同的值，則要先用 Split Temporary Variable（分解暫時變數）拆開。這篇用運費計算的例子說明兩者的用法和順序。

這兩個手法都出自 Martin Fowler《Refactoring》中「組合方法（Composing Methods）」這一類，以下的說明和範例是我自己的整理。

Replace Temp with Query：用方法取代暫時變數

什麼時候用

把某個表達式的結果存在區域變數裡，等一下再用。這個變數讓長方法很難再拆：任何想拆出去的程式碼，只要用到它，就得多一個參數。

好處

  • 可讀性：totalWeight() 一看就知道是什麼，比一長串 stream 運算好懂
  • 可重用、減少重複：同一個表達式常常也出現在其他方法裡，例如 packagingFee() 也需要總重量，現在直接呼叫 totalWeight() 即可
  • 讓長方法變得好拆：變數消失之後，方法裡的任何片段都可以直接 Extract Method，不用再傳參數

效能怎麼辦？

會多呼叫幾次方法，所以確實會多一點成本。但在現代的 CPU 和 JIT 編譯器下，這點成本幾乎都可以忽略，換來的可讀性和重用性通常更有價值。

例外是：如果這個表達式真的很耗時（例如查資料庫、呼叫外部 API），那麼做到「提煉成方法」就好，在呼叫端仍然用變數保存結果，不要每次都重新查。

步驟

  1. 確認這個變數在方法裡只被賦值一次。如果被賦值了好幾次，先用下面的 Split Temporary Variable 拆開
  2. 用 Extract Method 把計算這個變數的表達式搬進新方法
  3. 確認新方法只回傳值、不改變物件狀態。如果它會改變狀態，要先把「查詢」和「修改」拆成兩個方法
  4. 把用到這個變數的地方換成呼叫新方法，刪掉變數

Split Temporary Variable：一個變數只做一件事

什麼時候用

同一個區域變數在方法裡被重複賦值，用來存放意義不同的中間值（累加用的變數和迴圈變數除外）。這種變數沒辦法直接 Replace Temp with Query，因為它根本不代表單一個值。

為什麼要做

為了少宣告幾個變數，把同一個變數拿來存不相干的值，之後一修改就容易出錯：每次都得重新確認，在某一行拿到的到底是哪個值。

好處

  • 每個變數只負責一件事：改其中一個，不用擔心影響另一個
  • 可以順便取好名字：匆忙寫下的 result、temp、value，換成 subtotal、totalWithTax 這種一看就懂的名稱
  • 為下一步鋪路：拆開並加上 final 之後，每個變數都只被賦值一次，就可以接著做 Replace Temp with Query 或 Extract Method

步驟

  1. 找到變數第一次被賦值的地方，依照這個值的意義改成新名稱，並宣告成 final
  2. 在使用這個值的地方都改用新名稱
  3. 對變數之後每一次被賦予不同意義的值，重複上述步驟

兩者的順序

  1. 變數被重複賦值、代表不同意義 → 先 Split Temporary Variable
  2. 每個變數都只被賦值一次 → 再 Replace Temp with Query
  3. 變數都變成方法之後 → 長方法就能輕鬆地 Extract Method
