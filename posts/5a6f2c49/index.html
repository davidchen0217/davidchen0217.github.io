Nginx 負載平衡設定：round-robin、least_conn、ip_hash 與權重

發表於 2020-06-29 更新於 2026-11-27 分類於 Nginx 閱讀次數： Disqus： 文章字數： 2k 所需閱讀時間 ≈ 4 分鐘

把流量分散到多台應用程式伺服器，可以提高資源使用率和吞吐量、降低延遲，也能在某台機器故障時繼續提供服務。Nginx 本身就是很有效率的 HTTP 負載平衡器。這篇整理 Nginx 的四種負載平衡設定：預設的 round-robin、最少連線 least_conn、讓同一個使用者固定連到同一台的 ip_hash，以及用 weight 調整分配比例。

官方說明可參考 nginx.org 的〈Using nginx as HTTP load balancer〉，以下是我的整理和範例。

三種分配方式

方式設定怎麼選伺服器適合
round-robin預設，不用設定依序輪流分配每個請求處理時間差不多
least-connectedleast_conn;分給目前連線數最少的伺服器請求處理時間長短不一
ip-haship_hash;依用戶端 IP 的雜湊值決定需要 session 黏著（sticky session）

round-robin（預設）

假設有三台跑同一個應用程式的 Tomcat：

  • upstream 定義一組後端伺服器，名稱自訂
  • proxy_pass 把請求轉給這組伺服器
  • 沒有指定分配方式時，預設就是 round-robin：請求依序輪流分給三台

後端是 HTTPS 的話，proxy_pass 改用 https://。除了 HTTP，Nginx 也能對 FastCGI、uwsgi、SCGI、memcached、gRPC 做負載平衡，分別用 fastcgi_pass、uwsgi_pass、scgi_pass、memcached_pass、grpc_pass。

least_conn：分給最閒的伺服器

有些請求很快、有些很慢時（例如有報表匯出、大檔案下載），round-robin 可能讓某台累積很多還沒處理完的請求。least_conn 會把新的請求分給目前連線數最少的伺服器，避免忙碌的機器被塞爆：

ip_hash：同一個使用者固定連到同一台

round-robin 和 least_conn 都不保證同一個使用者的下一個請求會到同一台伺服器。如果 session 存在各台伺服器的記憶體裡，使用者換到另一台就會被登出。

ip_hash 用用戶端的 IP 計算雜湊值來決定伺服器，同一個 IP 會一直被導到同一台，除非那台無法使用：

要注意：

  • 很多使用者透過同一個公司 NAT 或代理伺服器上網時，他們的 IP 相同，會全部集中到同一台，分配可能不平均
  • 更根本的做法是把 session 放到 Redis 之類的共用儲存，讓每一台都能處理任何使用者的請求，就不需要 sticky session。Tomcat 的做法見 Redisson Tomcat Session Manager

weight：依機器規格調整比例

伺服器規格不同時，可以用 weight 讓效能好的機器分到比較多請求：

沒寫 weight 的預設是 1。上面的設定下，每 5 個請求大約有 3 個到 10.0.0.11，另外兩台各 1 個。新版的 Nginx 也可以在 least_conn 和 ip_hash 搭配 weight 使用。

補充：故障偵測

Nginx（開源版）用被動健康檢查：轉送失敗時，暫時把該伺服器標記為無法使用。

  • max_fails=3 fail_timeout=30s：30 秒內失敗 3 次，就在接下來的 30 秒內不再分配請求給它
  • backup：備援伺服器，平常不分配，其他伺服器都無法使用時才啟用
