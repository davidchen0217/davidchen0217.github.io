這篇整理我們在 Java 專案中用 High Level REST Client 操作 ElasticSearch 的做法：Maven 設定、帶帳號密碼的連線、update 與 search 範例、常用的 Range / Term / Should 查詢（附 Dev Tools 的 Query DSL 對照），以及超過 10000 筆時如何用 search_after 分頁查完所有資料。

Java High Level REST Client 從 ElasticSearch 7.15 起已被標為 deprecated，官方建議新專案改用 Elasticsearch Java API Client。以下內容適用於 7.x 的既有專案。

filter 與 must 的差別

  • filter：只判斷符不符合，不計算相關性分數，而且結果可以被快取，效能較好。精確比對、範圍查詢優先用 filter
  • must：符合才回傳，會計算分數，適合全文檢索
  • should：OR 條件，至少符合一個

查詢超過 10000 筆：search_after

ElasticSearch 預設的 index.max_result_window 是 10000，用 from + size 分頁時，超過 10000 筆就會報錯。要查出所有資料，改用 **search_after**：依照排序值，從上一頁最後一筆之後繼續查。

search_after 一定要搭配排序，而且排序欄位要能唯一識別每一筆資料（可以加一個唯一欄位當作 tiebreaker），否則 getSortValues() 會是空的：

資料在查詢期間持續寫入的話，分頁之間可能看到不一致的結果。需要一致的快照時，可以搭配 Point in Time（PIT）（7.10 以後）。
