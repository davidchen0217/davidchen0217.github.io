重構手法 Extract Variable 與 Inline Temp：用有意義的變數拆解複雜表達式

發表於 2020-06-18 更新於 2026-11-26 分類於 Refactor 閱讀次數： Disqus： 文章字數： 2.7k 所需閱讀時間 ≈ 5 分鐘

一行 if 裡塞了四、五個條件，每次讀都要停下來拆解？Extract Variable（提煉變數）就是把複雜表達式的各個部分，放進名稱能說明意義的變數裡。它的反向操作 Inline Temp（內聯暫時變數）則是把多餘的暫時變數拿掉。這篇用折扣判斷的例子說明兩者的用法，以及提煉變數時要注意的短路求值問題。

這兩個手法都出自 Martin Fowler《Refactoring》中「組合方法（Composing Methods）」這一類，以下的說明和範例是我自己的整理。

Extract Variable：替表達式的每個部分取名字

什麼時候用

當一個表達式很難一眼看懂時，例如：

  • if 或三元運算子 ?: 的條件很長
  • 一長串沒有中間結果的算式
  • 一行裡串了很多呼叫，被迫換好幾行

好處

  • 可讀性：變數名稱直接說明每個條件的業務意義，可以少寫很多註解
  • 方便除錯：每個中間結果都有名字，下中斷點就能看到各自的值
  • Extract Method 的前一步：如果某個提煉出來的表達式在其他地方也用得到，下一步就可以把它再提煉成方法，例如 customer.isMemberOverOneYear()

要注意：短路求值

&& 和 || 有短路求值：if (a() || b()) 中，如果 a() 回傳 true，b() 根本不會被呼叫。

b() 每次都會被執行。如果 b() 是很耗時的運算（例如查資料庫），或者有副作用，就要小心。這時候改用 Extract Method，把條件包成方法，就能保留短路的效果。

步驟

  1. 在表達式前面新增一行，宣告一個新變數，把表達式的某一部分賦值給它
  2. 用這個變數取代表達式中的那一部分
  3. 對表達式中每個複雜的部分重複上述步驟
  4. 盡量把變數宣告成 final，表明它只代表一個值

Inline Temp：拿掉多餘的暫時變數

什麼時候用

Extract Variable 的反向操作。如果一個暫時變數只是存放一個簡單表達式的結果，名稱也沒有比表達式本身提供更多資訊，就直接用表達式取代它。

要注意：不要拿掉有快取作用的變數

有些看似多餘的暫時變數，其實是用來保存一個昂貴運算的結果，而且後面會用好幾次：

這種變數 inline 之後會變成查三次資料庫。內聯之前，要先確認不會因此造成效能問題或重複的副作用。

步驟

  1. 找出所有使用這個變數的地方，換成原本賦值給它的表達式
  2. 刪除變數的宣告和賦值

怎麼拿捏？

  • 表達式的意義不明顯 → Extract Variable，用名字說明它代表什麼
  • 變數的名字沒有比表達式本身更清楚，而且只用一次 → Inline Temp
