Redisson 連線錯誤排查：WriteRedisConnectionException 與 RedisTimeoutException 的原因與調整方式

發表於 2022-07-26 更新於 2026-11-27 分類於 Redisson 閱讀次數： Disqus： 文章字數： 1.9k 所需閱讀時間 ≈ 3 分鐘

使用 Redisson 時遇到 WriteRedisConnectionException: Unable to write command into connection! Increase connection pool size 或 RedisTimeoutException，錯誤訊息叫你加大連線池，但真正的原因不一定是連線不夠。這篇整理這兩個錯誤常見的四個原因、Redisson 官方建議的調整順序，以及為什麼 Redis 的 slowlog 裡可能找不到那個慢指令。

錯誤訊息

從訊息可以看出：執行的是一段 Lua script（EVAL，Redisson 的 RMap.put 等操作底層就是 Lua script），重試 3 次後仍然無法把指令寫進連線。

另一個常見的類似錯誤是 RedisTimeoutException：指令送出了，但在 timeout 時間內沒有收到回應。

四個常見原因

依照 Redisson 官方 FAQ 的說明，這類錯誤主要有四個原因：

原因說明
Netty 執行緒都在忙Redisson 用 Netty 執行緒送出指令和解析回應，執行緒不夠時兩者都會延遲
連線都在使用中連線池裡沒有空閒的連線可用
Redis 回應太慢Redis 本身處理很慢，例如執行了很重的指令
在 async / reactive 的 listener 裡呼叫同步方法同步方法會卡住 Netty 執行緒，形成死結般的等待

調整順序

官方建議依這個順序調整：

1. 加大 nettyThreads

依序試 32、64、128、256，讓 Redisson 有空閒的 Netty 執行緒可以送指令和解析回應：

2. 調整 retryInterval 和 timeout

把它們調到合理的值：在網路短暫抖動時能撐過去，但真的有問題時也能適時失敗，不要讓使用者一直等：

3. 最後才加大連線池

雖然錯誤訊息寫著「Increase connection pool size」，但如果根本原因是 Redis 慢或執行緒不夠，只加大連線池只會讓更多請求一起卡住。

先檢查有沒有很重的指令

比較容易觸發這類錯誤的，是複雜或大量資料的指令：

  • KEYS（正式環境應該禁用，改用 SCAN）
  • 一次取很多欄位的 HMGET、HGETALL
  • Lua script 裡有大迴圈
  • 對 bigkey 的操作

這些指令會讓 Redis（單執行緒）在執行期間無法處理其他請求，所有用戶端都一起變慢。找出 bigkey 的方法見 Redis 基礎與 Key 設計規範。

為什麼 slowlog 裡找不到？

Redis 的 slowlog 只記錄指令在 Redis 事件迴圈中實際執行的時間，不包含：

  • 指令在 Redis 排隊等待執行的時間（前面有慢指令擋著）
  • 網路傳輸的時間
  • 用戶端 Netty 執行緒處理的時間

所以即使 slowlog 裡沒有任何慢指令，用戶端仍然可能 timeout。另外，網路問題也會在回應還在傳輸途中時造成這個錯誤。排查時要同時看 Redis 的 CPU、用戶端的執行緒狀況和網路品質。
