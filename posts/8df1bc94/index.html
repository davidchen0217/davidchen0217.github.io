組合模式（Composite）：用樹狀結構表示部分與整體，透明方式與安全方式的取捨

發表於 2024-10-25 更新於 2026-11-27 分類於 ObjectOrientedProgramming 閱讀次數： Disqus： 文章字數： 2.7k 所需閱讀時間 ≈ 5 分鐘

這篇是《大話設計模式》組合模式的讀書筆記：用樹狀結構表示「部分與整體」的階層，讓用戶端可以用同樣的方式處理單一物件（葉節點）和組合物件（樹枝）。包含基本結構、透明方式和安全方式的差別、使用時機與好處。

定義

組合模式：將物件組合成樹狀結構，以表示「部分 - 整體」的階層結構。組合模式讓用戶端對單一物件和組合物件的使用具有一致性。

透明方式 vs 安全方式

葉節點不能再長出分枝，為什麼 Leaf 也有 Add 和 Remove？這是兩種實作方式的取捨：

透明方式安全方式
做法在 Component 宣告所有管理子物件的方法（Add、Remove），所有子類別都具備Component 不宣告 Add、Remove，只在 Composite 宣告
優點葉節點和樹枝對外沒有區別，介面完全一致葉節點不需要實作沒有意義的方法
缺點葉節點本身沒有 Add、Remove 的功能，實作它們沒有意義不夠透明：葉節點和樹枝介面不同，用戶端呼叫前要先判斷是哪一種

上面的範例用的是透明方式。

什麼時候使用

  • 需求中有部分與整體的階層結構時
  • 希望用戶端可以忽略組合物件和單一物件的不同，統一地使用組合結構中的所有物件時

常見的例子：

  • UI 元件樹：ASP.NET Web 控制項的基底類別 System.Web.UI.Control 就有 Controls.Add 和 Remove；網頁的 DOM 也是
  • 公司組織圖：總公司底下有分公司和部門，分公司底下又有部門
  • 檔案系統：資料夾裡有檔案和資料夾
  • 選單：選單裡有選項和子選單

好處

  • 定義了包含基本物件和組合物件的類別階層。基本物件可以被組合成更複雜的組合物件，組合物件又可以再被組合，不斷遞迴下去
  • 用戶端程式碼中，任何用到基本物件的地方都可以使用組合物件
  • 用戶端不需要關心處理的是葉節點還是組合元件，也不需要為了區分它們而寫判斷式
