原型模式（Prototype）：用 Clone 複製物件，以及淺複製與深複製的差別

發表於 2024-07-29 更新於 2026-11-27 分類於 ObjectOrientedProgramming 閱讀次數： Disqus： 文章字數： 2.4k 所需閱讀時間 ≈ 4 分鐘

這篇是《大話設計模式》原型模式的讀書筆記：為什麼用複製（Clone）建立物件比一直 new 更好、C# 的 MemberwiseClone 是淺複製，以及物件裡有參考型別的欄位時，如何實作深複製。

為什麼需要原型模式

一個物件要建立很多份時，一般的做法是 new 很多次。但每 new 一次就要執行一次建構子，如果建構子的初始化很耗時（例如要讀檔、查資料庫），程式效率就會變差。

在初始化資訊不會改變的情況下，複製一個已經初始化好的物件是更好的方法：

  • 隱藏了建立物件的細節
  • 不用重新執行耗時的初始化，效能大幅提升

淺複製與深複製

淺複製（Shallow Copy）

MemberwiseClone() 是淺複製：

  • 值型別的欄位（int、struct）：複製值，新舊物件各自獨立
  • 參考型別的欄位（物件）：只複製參考（記憶體位址），新舊物件指向同一個被參考的物件

string 雖然是參考型別，但它是不可變的，修改時會產生新字串，所以用起來像值型別，淺複製沒有問題。

淺複製後，a、b、c 三份履歷的 work 指向同一個物件。改了 b 的工作經歷，a 和 c 也一起被改了。

深複製（Deep Copy）

深複製會把參考型別的欄位也複製一份新的，讓複製出來的物件指向新的被參考物件：

參考的層次越深，深複製要處理的就越多，也要注意循環參考的問題。

.NET 裡的例子

DataSet 同時提供兩種複製：

  • Clone()：只複製 DataSet 的結構，不複製資料
  • Copy()：結構和資料都複製，相當於深複製

Java 的對照

Java 的 Object.clone() 預設也是淺複製。實務上常用複製建構子、或透過序列化（例如轉成 JSON 再轉回來）來做深複製，比實作 Cloneable 更不容易出錯。
