Docker Compose 安裝與常見錯誤排解：command not found、orphan containers、no configuration file、Volume 變成目錄

發表於 2024-02-27 更新於 2026-11-26 分類於 DockerCompose 閱讀次數： Disqus： 文章字數： 2.5k 所需閱讀時間 ≈ 5 分鐘

這篇整理我們在 Rocky Linux 上安裝和使用 Docker Compose 遇過的問題：安裝方式、line 1: Not: command not found、Found orphan containers、no configuration file provided: not found，以及掛載設定檔時 container 裡卻變成一個目錄的原因與正確順序。

在 Rocky Linux 安裝 Docker Compose

方法一：下載獨立的 docker-compose 執行檔

建議加上 -f（curl -fL），下載失敗時 curl 會直接回傳錯誤，而不是把錯誤頁面存成執行檔（下一節的問題就是這樣來的）。

方法二：安裝 Docker Compose v2 plugin

如果是用 Docker 官方的 repo 安裝 Docker CE，可以直接裝 plugin，之後用 docker compose（中間是空白）執行：

line 1: Not: command not found

情境：安裝完執行 docker-compose，出現：

原因：下載的根本不是執行檔。下載網址錯誤時，GitHub 回傳的是內容為 Not Found 的文字，curl 把它存成了 docker-compose。加上執行權限後，shell 把這個文字檔當成 script 執行，第一行的 Not 就變成「找不到指令」。

檢查方式：看檔案大小是否異常（正常的執行檔有數十 MB，錯誤的只有幾個 byte），或直接看內容：

解法：確認下載網址和版本正確後重新安裝，並使用 curl -fL。

Found orphan containers

情境：執行 docker-compose up -d 出現警告：

原因：Docker Compose 用「專案名稱」（預設是 compose 檔所在的目錄名稱）來管理 container。如果 compose 檔裡的 service 被刪除或改名，或同一個目錄下用了不同的 compose 檔，屬於同一個專案、但不在目前 compose 檔裡的 container 就會被視為 orphan。

如果它們其實是另一組服務，應該用 -p 或 COMPOSE_PROJECT_NAME 給不同的專案名稱，而不是刪掉它們。

Volume 掛載設定檔，container 裡卻變成目錄

情境：要把一個設定檔掛載到 Tomcat container 的 /tomcat/lib 底下。我們的做法是：先在 docker-compose 的 yml 加上 volume 設定、重啟服務，之後才把設定檔上傳到主機。結果不管怎麼重開、怎麼重新上傳，container 裡看到的永遠是一個目錄，而不是設定檔。

原因：bind mount 的主機路徑如果還不存在，Docker 會自動在主機上建立一個同名的目錄。所以第一次啟動時，app-config.properties 在主機上就被建成了目錄；之後再上傳設定檔，也只是放進那個目錄裡，container 掛載的依然是目錄。

解法：順序很重要。

  1. 先把設定檔上傳到主機的 /tomcat/lib/
  2. 再在 docker-compose 的 yml 加入 volume 設定
  3. 重啟服務
