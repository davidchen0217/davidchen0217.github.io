Dockerfile 實戰：常用指令、ENTRYPOINT 與 CMD、Rocky Linux + Tomcat 10 + JDK 17 映像檔範例與映像檔拉取策略

發表於 2023-04-12 更新於 2026-11-27 分類於 Docker 閱讀次數： Disqus： 文章字數： 4.3k 所需閱讀時間 ≈ 8 分鐘

這篇整理撰寫 Dockerfile 的筆記：常用指令、ENTRYPOINT 和 CMD 怎麼搭配、一個 CentOS + Apache 的簡單範例，以及我們實際使用的 Rocky Linux 8 + Tomcat 10 + JDK 17 映像檔：依照 container 的記憶體上限自動計算 JVM heap。最後補充映像檔的拉取策略（Kubernetes 的 imagePullPolicy 與 Docker 的 --pull）。

常用指令

指令說明
FROM從哪一個映像檔開始建置
LABEL加上 metadata，例如說明、維護者
RUN建置時執行的指令，每個 RUN 都會產生一層 layer
COPY把建置環境（context）的檔案複製進映像檔
ADD和 COPY 類似，但會自動解開本機的 tar 檔、也能下載 URL。一般情況建議用 COPY，比較明確
ENV設定環境變數
EXPOSE宣告 container 會用到的 port（只是文件用途，實際對外還是要 -p）
ENTRYPOINTcontainer 啟動時執行的程式
CMD預設參數；沒有 ENTRYPOINT 時則是預設執行的指令

範例一：CentOS 7 + Apache

container 的生命週期跟著主程式走：主程式結束，container 就會停止。httpd 預設會轉到背景執行（daemon），主程式一結束 container 就停了，所以要用 -D FOREGROUND 讓它留在前景。

注意 Dockerfile 的註解只能用 #，而且要獨立一行，不能用 // 或寫在指令後面。

目錄結構

Dockerfile

ENTRYPOINT 用 sh -c '... && "$@"' -s 的寫法：先執行 env.sh 設定環境變數，再把 CMD（catalina.sh run）當成參數執行，讓 Tomcat 能讀到計算好的 XMX / XMS。

run.sh：建置時執行一次

注意：在 RUN 裡刪除前面 COPY 進來的壓縮檔，不會讓映像檔變小，因為壓縮檔仍然存在於 COPY 那一層 layer。要真正減少大小，可以用 multi-stage build，或改用 ADD 直接解壓縮。

env.sh：依 container 記憶體上限計算 JVM heap

setenv.sh 再用 -Xmx${XMX}g -Xms${XMS}g 帶給 JVM。

兩點補充：

  • 這個腳本讀的是 cgroup v1 的路徑。新版的 Linux（例如 Rocky Linux 9）預設使用 cgroup v2，上限要改讀 /sys/fs/cgroup/memory.max
  • JDK 10 以後的 JVM 本身就能感知 container 的記憶體上限，也可以改用 -XX:MaxRAMPercentage=60 讓 JVM 自動依比例計算，不需要自己寫腳本

映像檔拉取策略

Kubernetes：imagePullPolicy

值行為
Always不管本機有沒有下載過，每次都重新下載
IfNotPresent本機已經有就直接用；沒有或被清掉了才下載
Never永遠不下載，直接用本機的；本機沒有就報錯

沒有指定時，tag 是 latest 或沒寫 tag 的預設是 Always，其他 tag 預設是 IfNotPresent。所以正式環境建議使用明確的版本號 tag，不要用 latest。
