Jedis 使用筆記：Redis 五種資料結構、Transaction、Pipeline、Pub/Sub 與 JedisPool 連線池

發表於 2020-07-21 更新於 2026-11-27 分類於 Redis 閱讀次數： Disqus： 文章字數： 5k 所需閱讀時間 ≈ 9 分鐘

Jedis 是 Redis 官方推薦的 Java client 之一，API 和 Redis 指令幾乎一對一，很好上手。這篇整理用 Jedis 操作 Redis 的方式：String、List、Set、Hash、Sorted Set 五種資料結構的常用指令，用 Transaction（MULTI / EXEC）確保多個指令一起執行，用 Pipeline 減少網路來回，Pub/Sub 訂閱發布，以及正式環境一定要用的 JedisPool 連線池設定。

五種資料結構

以下用一個電商網站的例子示範。

String：最基本的 key-value

List：依插入順序排列，適合當佇列

左進右出（LPUSH + RPOP）就是先進先出的佇列，先放進去的會先被取出。

Set：不重複的集合

SISMEMBER 判斷某個元素在不在集合裡是 O(1)，很適合做「是否看過、是否按過讚」的判斷。

Hash：一個 key 底下有多個欄位

適合存物件：要讀或改某個屬性時，不需要把整個物件取出來再存回去。

Sorted Set：帶分數、自動排序

排行榜、依時間排序的資料都很適合用 Sorted Set。

Transaction：多個指令一起執行

MULTI / EXEC 讓多個指令依序一起執行，執行期間不會插入其他用戶端的指令：

要注意 Redis 的 Transaction 不支援回滾：其中一個指令失敗，其他指令還是會執行。

需要「某個 key 在交易期間沒被別人改過才執行」時，在 multi() 之前用 WATCH。被監看的 key 一旦被修改，exec() 就不會執行任何指令並回傳 null，程式可以重試：

Pipeline：減少網路來回

一般情況下，每個指令都要等 Redis 回應後才送下一個。指令很多時，網路來回的時間會遠大於 Redis 執行的時間。Pipeline 把多個彼此不相依的指令一次送出，再一次取回所有結果：

在 sync() 之前呼叫 Response.get() 會拋出例外，因為指令還沒真正送出。

Pipeline 只是網路優化，不保證原子性；需要原子性要用 Transaction 或 Lua script。
