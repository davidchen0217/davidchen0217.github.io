裝飾模式與代理模式：動態增加功能 vs 控制存取，以及四種常見的代理

發表於 2024-07-23 更新於 2026-11-27 分類於 ObjectOrientedProgramming 閱讀次數： Disqus： 文章字數： 1.7k 所需閱讀時間 ≈ 3 分鐘

這篇是《大話設計模式》裝飾模式與代理模式的讀書筆記。兩者的結構很像，都是一個物件包住另一個物件，但目的不同：裝飾模式是動態地替物件增加功能，代理模式是控制對物件的存取。最後整理遠端代理、虛擬代理、安全代理、智慧代理四種常見的代理。

裝飾模式（Decorator）

解決什麼問題

系統需要新功能時，最直覺的做法是在舊類別裡加程式碼。但這些新功能通常只是裝飾原本的核心職責，而且只在某些特定情況下才需要。把它們都塞進主類別，會讓主類別多出很多欄位、方法和判斷，越來越複雜。

裝飾模式的做法是：把每個要裝飾的功能放在單獨的類別中，讓這個類別包住它所要裝飾的物件。需要特殊行為時，用戶端在執行期間依需要、依順序選擇要套上哪些裝飾。

好處

  • 把裝飾功能從原本的類別中搬出去，簡化原有的類別
  • 有效地把類別的核心職責和裝飾功能區分開
  • 可以去除相關類別中重複的裝飾邏輯

要注意

裝飾的順序可能很重要。最理想的情況是裝飾類別之間彼此獨立，這樣就能以任意順序組合。

範例

Java 的 I/O 就是經典的裝飾模式：一層一層包上緩衝、解壓縮等功能，每一層都不知道裡面包的是什麼：

代理模式（Proxy）

定義

為其他物件提供一個代理，以控制對這個物件的存取。

基本結構

代理和真實物件實作同一個介面，所以用戶端可以把代理當成真實物件使用。

四種常見的代理

種類用途例子
遠端代理替位於不同位址空間（另一台機器）的物件提供本機代表，隱藏物件在遠端的事實在專案加入 Web Service 參考時產生的 proxy 類別：呼叫它就像呼叫本機物件
虛擬代理需要時才建立耗費資源的物件，先用代理替代網頁先顯示圖片的佔位框（代理記住圖片路徑和尺寸），真正的圖片之後才載入
安全代理控制存取真實物件的權限檢查使用者權限後才轉呼叫
智慧代理呼叫真實物件時，順便處理其他事計算物件被參考的次數，沒人參考時自動釋放；第一次參考持久化物件時才把它載入記憶體

共通點都是在存取物件時加入一層間接性，利用這層間接性附加各種用途。

現代框架裡最常見的例子是 Spring AOP：@Transactional 背後就是代理物件，在呼叫真正的方法前後幫你開始和提交交易。

裝飾模式 vs 代理模式

裝飾模式代理模式
目的增加功能控制存取
誰決定包裝用戶端依需要自由組合多層裝飾通常由代理自己決定何時建立、是否轉呼叫真實物件
層數經常一層包一層通常只有一層
