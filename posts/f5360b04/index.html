Docker 基本操作筆記：Port 轉發、Volume 持久化、Bridge 網路、重啟策略、更新映像檔與私有 Registry

發表於 2023-05-15 更新於 2026-11-27 分類於 Docker 閱讀次數： Disqus： 文章字數： 3.2k 所需閱讀時間 ≈ 6 分鐘

這篇整理使用 Docker 和 Docker Compose 的基本操作：用 -p 做 port 轉發、用 Volume 讓資料不隨 container 消失、在 Compose 裡設定 bridge 網路和固定 IP、設定 container 不要自動重啟、更新映像檔版本的步驟，以及架設和使用私有 Registry。

Volume：讓資料不會消失

container 內的檔案系統是暫時的：container 被刪除時，裡面的資料也會一起消失；從映像檔重建 container，也會回到映像檔原本的狀態。

會變動、需要保留的資料，例如設定檔、資料庫檔案、上傳的檔案，要用 -v 掛載到主機上：

這樣即使刪掉 container 再重建，只要掛載同一個主機路徑，資料都還在。

  • bind mount（-v /主機/路徑:/container/路徑）：直接對應主機的目錄，方便查看和備份
  • named volume（-v 名稱:/container/路徑）：由 Docker 管理存放位置，可攜性較好

掛載單一設定檔時要注意：主機上的檔案必須先存在，否則 Docker 會建立一個同名的目錄，詳見 Docker Compose 常見錯誤排解。

Bridge 網路（Docker Compose）

bridge 是 Docker Compose 預設的網路模式。執行 docker compose up 時，會建立一個名為 <目錄名>_default 的網路，所有 service 都接上這個網路，彼此可以用 service 名稱互相連線。

需要固定 IP 或自訂網段時，可以自己定義網路：

同一個網路上的 container 之間是互通的，可以用 ping 測試。

注意事項：

  • 自訂的網段不要和公司內網或 VPN 的網段重疊，否則主機可能連不到那些網段（192.168.0.0/16 很容易撞到）
  • 新版 Docker Compose 已經不需要檔案開頭的 version: 欄位

重啟策略：不要自動重啟

restart 決定 container 停止後要不要自動重啟：

值行為
"no"（預設）不自動重啟
always不管什麼原因停止都重啟，Docker daemon 重啟後也會啟動
on-failure只有異常結束（exit code 非 0）才重啟
unless-stopped和 always 類似，但被手動 stop 的不會在 daemon 重啟後自動啟動

  • insecure-registries：允許用 HTTP 連線的 Registry。只建議用在內網的測試環境，正式環境應該替 Registry 設定 TLS 憑證
