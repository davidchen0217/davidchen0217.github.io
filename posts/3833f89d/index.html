C# static class 與一般類別的差異：不能建立實例、只能有靜態成員、不能被繼承

發表於 2020-04-21 更新於 2026-11-27 分類於 CSharp 閱讀次數： Disqus： 文章字數： 1.6k 所需閱讀時間 ≈ 3 分鐘

C# 的 static class 和一般（非靜態）類別有什麼不同？什麼時候該用 static class？這篇用表格比較兩者在建立實例、成員、建構子和繼承上的差異，並附上範例。

差異比較

static class一般類別
宣告加上 static 關鍵字不加 static
建立實例不能 new可以 new 出多個實例
存取成員直接用類別名稱存取靜態成員用類別名稱，實例成員要透過物件
成員只能有靜態成員可以同時有靜態和實例成員
建構子不能有實例建構子，只能有靜態建構子可以有實例建構子和靜態建構子
繼承不能被繼承，也不能繼承其他類別（只能隱含繼承 object）可以繼承和被繼承

什麼時候用 static class

  • 只包含工具方法、常數，不需要保存狀態
  • 定義擴充方法

要注意 static class 很難在單元測試中替換（無法 mock），如果某個功能未來可能需要替換實作（例如寄信、讀取時間），比較好的做法是定義介面、用一般類別實作，再透過依賴注入使用。
