Redisson 設定與使用筆記：Cluster / Replicated / Sentinel 模式、讀取與訂閱模式、Pub/Sub、Sharded Topic 與升級注意事項

發表於 2020-08-10 更新於 2026-11-27 分類於 Redis 閱讀次數： Disqus： 文章字數： 5.6k 所需閱讀時間 ≈ 10 分鐘

Redisson 是 Redis 的 Java client，除了基本的讀寫，還提供分散式鎖、分散式集合、Pub/Sub 等功能。這篇整理我們專案中使用 Redisson 的設定與經驗：程式和 YAML 兩種設定方式、Cluster 與 Replicated 模式的重要參數、readMode / subscriptionMode 設錯導致 Pub/Sub 收不到訊息、RTopic 與 RShardedTopic 的差別，以及升級 Redisson 時遇過的 codec 與 slot 問題。

分散式鎖的用法另外整理在 Redisson 分散式鎖完整筆記。

重要參數

參數預設說明
scanInterval1000掃描叢集拓撲（Cluster）或 master 變化（Replicated）的間隔，毫秒
readModeSLAVE讀取用哪種節點：SLAVE（沒有 slave 時用 master）、MASTER、MASTER_SLAVE
subscriptionModeSLAVE訂閱 Pub/Sub 用哪種節點：SLAVE、MASTER
loadBalancerRoundRobin多個節點之間的負載平衡：RoundRobin、WeightedRoundRobin、Random
timeout3000指令送出後等待回應的時間，毫秒
retryAttempts / retryInterval3 / 1500指令送不出去時重試幾次、間隔多久；送出後就改由 timeout 計時
masterConnectionPoolSize / slaveConnectionPoolSize64每個節點的連線池上限
subscriptionConnectionPoolSize50Pub/Sub 連線池上限，RTopic、RLock、RSemaphore 等都會用到
subscriptionsPerConnection5每條訂閱連線最多訂閱幾個 channel
pingConnectionInterval0每條連線送 PING 的間隔，0 = 不送
password / usernamenullRedis 驗證；username 需要 Redis 6.0 以上（ACL）

讀寫分離要注意：Redis 的主從複製是非同步的，readMode: SLAVE 時剛寫入的資料可能還沒同步到 slave，讀不到最新值。

RShardedTopic：Redis 7 的 Sharded Pub/Sub

一般的 RTopic 在 Redis Cluster 裡，發布的訊息會廣播到所有節點，節點越多，浪費的網路頻寬越多。

Redis 7.0 加入了 Sharded Pub/Sub，Redisson 對應的是 RShardedTopic：

  • 依 topic 名稱對應到特定的 slot，訂閱和發布只在負責那個 slot 的節點上進行
  • 訊息不會廣播到整個叢集，降低網路頻寬和 Redis 的負擔
  • 重新連線或 failover 後會自動重新訂閱，但斷線期間的訊息一樣會遺失

升級 Redisson 的注意事項

codec 必須前後一致

Redisson 3.17.7 升級到 3.23.2 時，YAML 裡的 codec 必須維持和原本相同：

Redisson 的預設 codec 在不同版本之間改過好幾次（例如舊版是 FstCodec，後來改成 MarshallingCodec，再改成 Kryo）。沒有明確指定 codec 的話，升級後新版本會用新的 codec 去解讀舊資料，就會出現解碼錯誤。

  • 如果 Redis 有開持久化，資料會留到升級後，一定要明確指定和原本相同的 codec；真的要換 codec，就要處理舊資料的轉換
  • 如果 Redis 只當暫時性的快取、沒有持久化，只要升級前後的 YAML codec 一致，基本上不會有問題

Can’t add master for slot ranges

Redisson 3.16.6 升級到 3.16.8 後，初始化時出現：

原因：我們有 override Redisson 內部的 ClientConnectionsEntry 相關方法。3.16.6 可以正常運作，但 3.16.8 改了內部實作，原本 override 的方法對不上。

解法：依新版本重新 override 對應的方法，或直接移除原本的 override，就能在 3.16.8 正常運作。

覆寫函式庫的內部類別，等於綁死了它的實作細節，每次升級都可能壞掉。能用公開的設定或擴充點解決，就不要 override 內部方法。
