Redis 常見錯誤排解：OOM command not allowed、ERR AUTH called without any password、overcommit_memory 警告

發表於 2023-06-27 更新於 2026-11-27 分類於 Redis 閱讀次數： Disqus： 文章字數： 2.4k 所需閱讀時間 ≈ 4 分鐘

這篇整理維運 Redis 時遇過的三個錯誤和警告：記憶體用到上限時出現的 OOM command not allowed when used memory > 'maxmemory'、沒設定密碼卻呼叫 AUTH 的 ERR AUTH ... called without any password configured，以及 Redis 啟動時的 WARNING overcommit_memory is set to 0。每個都附上原因和解法。

OOM command not allowed when used memory > ‘maxmemory’

錯誤訊息

原因

Redis 的記憶體用量已經達到 maxmemory 設定的上限，而且沒辦法再淘汰（evict）任何 key 來騰出空間，所以拒絕所有會增加記憶體的寫入指令。常見情況：

  • maxmemory-policy 是預設的 **noeviction**：滿了就直接拒絕寫入
  • 用的是 volatile-* 系列的策略，但大部分 key 沒有設定 TTL，沒有可以淘汰的 key
  • maxmemory 設得太小，或有 bigkey 佔掉大量記憶體

解法

  1. 確認目前用量和設定
  1. 調高 maxmemory：修改 Redis 的設定檔（依安裝路徑找到對應的 conf，例如 /usr/local/redis/redis_6.2.6/common.conf）：

不想重啟的話，也可以先在線上調整（重啟後會失效，記得同步改設定檔）：

  1. 選擇適合的淘汰策略：Redis 當快取用的話，通常設成 allkeys-lru，滿了就淘汰最久沒用的 key：
  1. 找出佔用記憶體的 key：用 redis-cli --bigkeys 找出 bigkey，並替該過期的資料設定 TTL

ERR AUTH <password> called without any password configured for the default user

錯誤訊息

原因

用戶端（程式或 redis-cli）送了 AUTH 密碼，但 Redis 伺服器根本沒有設定密碼。常見於程式的設定檔有填密碼，但 Redis 伺服器是剛裝好、還沒設定 requirepass 的狀態。

WARNING overcommit_memory is set to 0

警告訊息

Redis 啟動時出現：

原因

Redis 做 RDB 快照或 AOF 重寫時，會 fork() 出子行程。fork 之後父子行程共用記憶體分頁（copy-on-write），實際上不會用掉兩倍的記憶體，但 Linux 在 overcommit_memory=0 時，可能會因為「帳面上」需要的記憶體不足而拒絕 fork，導致背景存檔失敗。

vm.overcommit_memory 決定 kernel 怎麼處理大型的記憶體配置請求：

值行為
0（預設）啟發式判斷：估計可用記憶體，明顯超出的請求會被拒絕
1一律允許配置，不檢查。記憶體過度配置的機會增加，但對頻繁存取記憶體的程式效能較好
2嚴格模式：配置總量不能超過「swap + 實體記憶體 × overcommit_ratio」，最能降低過度配置的風險
