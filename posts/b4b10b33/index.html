Linux 系統資源與效能排查：vmstat、htop、清除記憶體快取、釋放 Swap、fork Resource temporarily unavailable、檔案描述符上限

發表於 2021-09-29 更新於 2026-11-27 分類於 Linux 閱讀次數： Disqus： 文章字數： 3.2k 所需閱讀時間 ≈ 6 分鐘

這篇整理排查 Linux 主機資源問題時常用的工具和設定：用 vmstat、htop 看 CPU、記憶體和 I/O；記憶體告警時手動清除快取、釋放 Swap；執行腳本出現 fork: retry: Resource temporarily unavailable 時調整 process 數上限；以及系統的檔案描述符（連線數）上限。

vmstat：一次看 CPU、記憶體、I/O

第一行是開機以來的平均值，要看即時狀況請看第二行之後的輸出。

區塊欄位意義
procsr可執行的 process 數（正在跑或等待 CPU）。長期大於 CPU 核心數，代表 CPU 不夠用
b處於不可中斷睡眠（通常是在等 I/O）的 process 數
memoryswpd已使用的 swap 空間
free完全沒被使用的記憶體
buff / cache被當成 buffer、檔案快取使用的記憶體
swapsi每秒從 swap（磁碟）讀回記憶體的量
so每秒從記憶體寫到 swap 的量。持續不為 0 代表記憶體不足
iobi / bo每秒從磁碟讀取 / 寫入的 block 數
systemin每秒中斷次數
cs每秒 context switch 次數（process 切換、遇到中斷時的狀態切換）
cpuus使用者程式佔用的 CPU 時間
sykernel 佔用的 CPU 時間
id閒置時間
wa等待 I/O 的時間。偏高代表磁碟是瓶頸
st虛擬機被 hypervisor「偷走」的時間。偏高代表實體主機資源被其他虛擬機搶走

htop：互動式的 process 監控

htop 比 top 更直覺：每個 CPU 核心的使用率、記憶體和 swap 都用長條圖顯示，可以用方向鍵選擇 process、直接排序或結束 process。

記憶體告警：手動清除快取

情境

在 Linux 上把 log 打包成 .tar.gz 時，觸發了「記憶體使用率超過 80%」的告警。用 free 觀察，打包完之後被快取（cache）的記憶體多了不少，而且不會隨著 process 結束馬上釋放。

先理解：快取不是真的被佔用

Linux 會把閒置的記憶體拿來當檔案快取，讓下次讀同一個檔案更快；需要記憶體時，kernel 會自動釋放快取。所以 free 的 free 欄位很小通常不是問題，要看的是 available 欄位：

如果監控是用「used + buff/cache」算使用率，就會在打包大檔案之後誤報。根本的解法是改用 available 計算記憶體告警。

強制清除快取

真的需要立即釋放時，可以寫入 /proc/sys/vm/drop_caches 讓 kernel 清除快取（先 sync 把還沒寫入磁碟的資料寫進去）：

清除後，後續讀取檔案會變慢一段時間（快取要重建），不建議排程定期執行。

釋放 Swap

記憶體曾經不足時，部分資料被搬到 swap；即使之後記憶體空出來了，這些資料也不會自動搬回來。可以用 swapoff / swapon 強制把 swap 裡的資料搬回記憶體。

檔案描述符與連線數上限

在 Linux 上，每一條 TCP 連線、每一個開啟的檔案都會佔用一個檔案描述符（file descriptor），所以檔案描述符的上限，也就決定了能同時維持多少連線。

系統層級的上限

file-nr 的三個數字分別是：已分配的數量、已分配但未使用的數量、系統上限（等於 file-max）。
