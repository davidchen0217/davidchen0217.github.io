範本方法模式（Template Method）：把不變的流程放在父類別，可變的步驟交給子類別

發表於 2024-08-06 更新於 2026-11-27 分類於 ObjectOrientedProgramming 閱讀次數： Disqus： 文章字數： 2.9k 所需閱讀時間 ≈ 5 分鐘

這篇是《大話設計模式》範本方法模式的讀書筆記：用「考卷」的例子說明如何把相同的題目搬到父類別、每個學生只寫自己的答案，再整理範本方法模式的基本結構和它解決的問題：去除子類別之間重複的不變行為。

範例：考卷

每個學生的考卷題目都一樣，只有答案不同。如果每個學生的考卷類別都自己寫一次題目，題目一改就要改好幾個地方。

把題目放在父類別 TestPaper，答案交給子類別：

子類別只剩下答案，題目改動只需要修改父類別。

基本結構

範本方法模式：定義一個操作中演算法的骨架，而將一些步驟延遲到子類別中。讓子類別可以不改變演算法的結構，就能重新定義演算法的某些特定步驟。

特點

  • 範本方法模式透過把不變的行為搬到父類別，去除子類別中重複的程式碼
  • 當不變和可變的行為混在子類別的實作中時，不變的部分就會在每個子類別重複出現。範本方法把不變的部分集中到一個地方，幫子類別擺脫重複
  • 這也是程式碼複用的一個基本技巧

實務上的例子

  • Java 的 AbstractList：實作好 indexOf、iterator 等流程，子類別只需要實作 get 和 size
  • Spring 的 JdbcTemplate：取得連線、建立 Statement、處理例外、關閉資源的流程都固定好，你只需要提供 SQL 和結果的對應方式
  • Servlet 的 HttpServlet.service()：依 HTTP method 分派到 doGet、doPost，子類別只要覆寫需要的方法

要注意繼承帶來的耦合：如果可變的步驟很多、或子類別需要在執行期間替換，可以考慮改用策略模式，用組合取代繼承。
