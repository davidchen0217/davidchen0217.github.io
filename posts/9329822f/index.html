用 Redisson 把 Tomcat Session 存到 Redis：RedissonSessionManager 設定與 readMode、updateMode 參數說明

發表於 2023-11-16 更新於 2026-11-27 分類於 Redisson 閱讀次數： Disqus： 文章字數： 1.9k 所需閱讀時間 ≈ 3 分鐘

多台 Tomcat 做負載平衡時，session 預設存在各自的記憶體裡，使用者被分到另一台就會被登出。Redisson 提供的 RedissonSessionManager 可以把 Tomcat 的 session 存到 Redis，讓每一台 Tomcat 都能讀到同一份 session，不再需要 sticky session。這篇整理安裝方式和每個參數的意思。

安裝

1. 放入 jar

把以下兩個 jar 放到 TOMCAT_BASE/lib 目錄：

  • redisson-all-3.24.3.jar
  • 對應 Tomcat 版本的 session manager，例如 Tomcat 10.x 是 redisson-tomcat-10-3.24.3.jar

2. 修改 conf/context.xml

configPath 指向 Redisson 的 YAML 設定檔，寫法和一般使用 Redisson 時相同，見 Redisson 設定與使用筆記。

參數說明

keyPrefix

加在所有 Redis key 前面的前綴。多個 Tomcat 環境（例如 staging 和 production）共用同一台 Redis 時，用不同的前綴區分，避免 session 互相覆蓋。

readMode：session 屬性從哪裡讀

值行為
REDIS（預設）session 屬性只存在 Redis，每次讀取都向 Redis 查詢
MEMORY屬性同時存在 Tomcat 本機記憶體和 Redis。讀取時直接讀本機，其他 Tomcat 的修改透過 Redis 的事件同步到本機

MEMORY 讀取比較快，但會多用 Tomcat 的記憶體；REDIS 每次讀都要查 Redis，但每台 Tomcat 看到的資料一定是最新的。

updateMode：session 屬性什麼時候寫回 Redis

值行為
DEFAULT（預設）只有呼叫 session.setAttribute(...) 時才寫入 Redis
AFTER_REQUEST請求結束後才一次寫入（見下方）

AFTER_REQUEST 在兩種 readMode 下的行為不同：

  • readMode=REDIS：同一個請求中透過 setAttribute 做的修改先累積在記憶體，請求結束後才一次寫入 Redis，減少寫入次數
  • readMode=MEMORY：請求結束後，不管有沒有呼叫 setAttribute，所有 session 屬性都會寫回 Redis

第二種情況很實用：如果 session 裡放的是物件，程式直接修改物件的內容（例如 cart.addItem(...)），而沒有再呼叫一次 setAttribute，DEFAULT 模式下這個修改不會被寫回 Redis；用 AFTER_REQUEST 就不會漏掉。

broadcastSessionEvents

設為 true 時，sessionCreated 和 sessionDestroyed 事件會廣播到所有 Tomcat，每一台註冊的 HttpSessionListener 都會被觸發。預設 false。

broadcastSessionUpdates

只在 readMode=MEMORY 時有作用。設為 true 時，session 的更新會廣播到所有 Tomcat，其他 Tomcat 會把本機快取中被更新的屬性移除，下次讀取時再從 Redis 重新載入。預設 true。

建議的組合

  • 一般情況：readMode="REDIS" + updateMode="AFTER_REQUEST"，資料一致、寫入次數少
  • 讀取量很大、session 不常改：readMode="MEMORY" + updateMode="AFTER_REQUEST"，讀取最快

session 裡的物件必須可以被序列化（實作 Serializable，或符合 Redisson 設定的 codec），否則無法存進 Redis。
