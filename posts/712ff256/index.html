轉接器模式（Adapter）：介面不相容時的轉接，以籃球翻譯和 .NET DataAdapter 為例

發表於 2024-10-06 更新於 2026-11-27 分類於 ObjectOrientedProgramming 閱讀次數： Disqus： 文章字數： 2.7k 所需閱讀時間 ≈ 5 分鐘

這篇是《大話設計模式》轉接器模式的讀書筆記：系統的資料和行為都正確、只是介面對不上時，如何用轉接器把一個既有類別的介面轉換成用戶端期望的介面。包含物件轉接器的基本結構、外籍球員需要翻譯的範例，以及 .NET 的 DataAdapter。

定義與使用時機

轉接器模式：將一個類別的介面轉換成用戶端希望的另一個介面，讓原本因為介面不相容而無法一起工作的類別可以一起工作。

  • 軟體開發中，系統的資料和行為都正確，但介面不符時，就該考慮用轉接器
  • 主要用在想複用一些既有的類別，但它們的介面又和複用環境的要求不一致的情況
  • 用戶端可以統一呼叫同一個介面，程式更簡單、直接、緊湊
  • 一般是雙方都不容易修改時才使用轉接器：如果是自己系統裡的類別，能直接統一介面就不需要轉接器

基本結構（物件轉接器）

原本筆記中轉接器類別被誤寫成和 Adaptee 同名，已改為 Adapter。

這種「轉接器內部持有被轉接的物件」的做法叫物件轉接器；另一種用多重繼承實作的叫類別轉接器，C# 和 Java 不支援類別的多重繼承，所以通常用物件轉接器。

.NET 裡的例子：DataAdapter

DataAdapter 是 DataSet 和資料來源之間的轉接器，透過 Fill（把資料填進 DataSet）和 Update（把變更寫回資料來源）來轉接。資料來源可能是 SQL Server、Oracle、Access 或 DB2，DataAdapter 讓程式在不同資料庫之間都能得到統一的 DataSet。

Java 的例子：Arrays.asList() 把陣列轉接成 List 介面；InputStreamReader 把位元組串流（InputStream）轉接成字元串流（Reader）。

轉接器 vs 外觀 vs 代理

模式目的
轉接器轉換介面，讓不相容的介面可以一起工作
外觀簡化介面，替一群子系統提供一個簡單的入口
代理介面不變，控制對物件的存取
